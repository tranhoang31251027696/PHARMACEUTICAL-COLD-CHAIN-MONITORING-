# Streaming certificate checker and binary64 policy boundaries

## Scope and independence

`src/streaming_checker.py` imports neither production code nor the legacy checker. It does not use the production priority heap, rank-containment comparator, or candidate profile. It shares NumPy, Python arithmetic, the specified finite contract and certificate format. Independence here is an implementation boundary, not independent human authorship, verified software, or protection against a shared mathematical mistake.

## Candidate enumeration lemma

For each distinct observed score, the checker independently constructs its threshold mask, counts actual positives and observations, records the candidate descriptor and exact feasibility ratio, and immediately releases the mask. Strict-score candidates use `>`; the declared omitted group is excluded; split-tie candidates use stable Python ordering by descending score and original row index. Thus the recorded candidate descriptors equal direct enumeration under the declared family. Integer count offset affects feasibility only, not the actual-TP priority. All-negative labels force abstention as in the agreed contract.

## Suffix winner lemma

Sort descriptors by nondecreasing exact feasibility ratio p. At policy alpha, inclusive feasibility selects exactly the suffix starting at lower_bound(p,alpha); strict feasibility selects the suffix starting at upper_bound(p,alpha). Precompute, by reverse induction, the maximum fixed lexicographic priority in every suffix. The returned suffix maximum is therefore exactly the exhaustive winner. Equal priorities cannot conceal distinct memberships within a single nested family: equal selected count identifies the same prefix. This is a standard suffix-maximum data structure, not a new general algorithmic primitive.

## Streaming consumer soundness proposition

Assume valid aligned finite inputs, fixed declared families/priorities and exact arithmetic. The checker first validates the input digest, specifications, critical set, full ordered certificate coverage and unique endpoint ownership. Its probe set contains every independently derived critical point, one midpoint per resulting open atom, and all certificate boundaries/midpoints. By the finite partition theorem, these probes suffice to check all winner counts and memberships. At each probe the suffix lemma supplies the correct winner; its membership bitset is reconstructed directly from the original scores and descriptor. Equality compares actual bitsets, not only selected counts. A single cursor walks the already validated ordered certificate cells. It checks all supplied witness memberships/IDs and changed-row counts, and derives divergent length/PSC and Boolean equivalence independently. Therefore acceptance establishes the same finite-domain obligations as direct mask enumeration, conditional on the implementation satisfying these lemmas.

Only the current winner mask for each version is retained. As alpha increases, feasible suffixes shrink and a discarded maximum cannot become feasible again; each descriptor becomes a winner at most once. Candidate-count enumeration and witness bitset reconstruction still cost O(NG) in the worst case. Sorting ratios and query bisections add O(G log G + (K+C) log G), with O(C log C + K log K) probe sorting, where C is certificate-cell count. Auxiliary storage is O(N+G+K+C) machine-sized descriptors plus fraction/integer operand costs; no G-by-N mask table or cache of all packed memberships is retained. Split-tie ordering adds O(N log N) work. Hashing, JSON parsing and Python object sizes have additional measured costs. This reduces retained mask materialization, not the worst-case O(NG) scanning time. With G=N, quadratic work remains possible.

The finite tests and 428-certificate replay are evidence about this implementation, not a machine-checked proof of it. Rejection tests include input binding, missing critical points, missing coverage, wrong winners/equality and altered metric/count fields.

## Public binary64 selector guard lemma

The new external case executes the unmodified installed eval-toolkit TargetPrecisionSelector. It accepts a binary64 policy value. The wrapper explicitly converts an exact rational policy a using CPython nearest/even `float(a)` and maps the documented no-feasible RuntimeError to abstention. Let p be an actual returned binary64 empirical precision, q=nextafter(p,+infinity), and c=(exact(p)+exact(q))/2. Within the positive finite domain considered, p >= float(a) holds exactly for a<c, plus a=c when p has an even significand. This follows from monotonic nearest/even rounding: numbers below the midpoint round no higher than p; above it round at least to q; the midpoint rounds to the even neighbor. The implementation checks midpoint ownership on the actual runtime and tests neighboring cells.

Each actual public guard therefore has an exact rational cut c with its own closure. The union of these cuts, the exact-reference k/n cuts and domain endpoints again yields a finite complete partition. We call the actual installed selector at every union breakpoint and midpoint and independently compare its output with the derived guard model. Smallest feasible threshold agrees with maximum selected count in the same nested family; maximizing (TP,N) also chooses that member since TP is nondecreasing with selected count. The candidate source, scorer, labels and scores remain policy-independent.

These are real differences between a rational-reference interface and a binary64 public interface. They are not necessarily changes between upstream versions, unmet upstream requirements, or confirmed bugs. Generic reasoning about rounding preimages and AllSMT region enumeration predates this study; the contribution here is the explicit contract mapping and checked selector-level diagnostics. Different rounding modes, non-binary64 scores, resampling, arbitrary code and hidden state are outside this admission argument.
